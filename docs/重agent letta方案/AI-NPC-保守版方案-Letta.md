# AI NPC 系统 — 保守版方案（基于 Letta）

> 版本：Conservative v1.0（定稿）
> 日期：2026-07-15
> 定位：**低风险、快落地、依赖成熟现成方案**。作为向管理层汇报时与"激进版"并列的**稳妥备选**。
> 核心选型：**Letta（前身 MemGPT）作为 Agent 层** · LLM 主导 · 云端部署 · **MVP 约 5 个 NPC**

---

## 0. 版本定位与设计决策

### 0.1 保守版的核心理念
- **不自研 Agent，不做独立 Social 层**：直接用成熟框架 Letta 承载 NPC 智能。
- **用"深度记忆"换"社交网络"**：Letta 的强项是单 NPC 的有状态长期记忆，NPC 的"生机"主要来自**每个 NPC 记得住、会成长**，而非复杂的 NPC 间社交图谱。
- **社交仅靠去中心化 NPC 记忆实现**：不建全局社交图，每个 NPC 用自己的记忆主观地"记住"他人。
- **最大化复用现成能力**：记忆、上下文管理、工具调用全部交给 Letta，团队只做"接入"与"配置"。

### 0.2 已确定的设计决策（本版基线）

| 决策项 | 结论 |
|--------|------|
| Agent 框架 | **Letta**（现成，有状态记忆） |
| 社交实现 | **仅靠去中心化的 NPC 记忆**（无全局社交图） |
| 群体协作 | **暂不实现** |
| NPC 规模 | **MVP 约 5 个**，无需考虑规模顾虑（不做休眠等机制） |
| CrewAI | **不引入**，保持纯 Letta 极简 |
| 版本关系 | **纯汇报备选**，不为激进版 Social 层预留接口 |
| 记忆耦合 | **接受**（采用现成 Agent 的必然取舍） |

### 0.3 与激进版的对比

| 维度 | 激进版 | 保守版（Letta） |
|------|--------|----------------|
| Agent | 自研薄决策器 | **Letta 现成框架** |
| 状态/记忆 | 外置 Social 层自研 | **Letta 内置有状态记忆** |
| 社交网络 | 独立社交图 + 演化 | **去中心化 NPC 记忆（无全局图）** |
| 群体协作 | 去中心化协商 | **不实现** |
| 开发成本 | 高 | **低** |
| 风险 | 高 | **低** |
| "生机"来源 | 社区级社交涌现 | **单 NPC 记忆与成长** |

### 0.3 Letta 是什么（选型依据）
Letta（原 MemGPT）是**有状态 Agent 平台**，核心能力：
- **分层记忆**：核心记忆（core）/ 归档记忆（archival）/ 召回记忆（recall），Agent 像操作系统管内存一样自主换入换出。
- **跨重启持久**：每个 Agent 是持久实体，长期记住人和事。
- **自主记忆管理**：Agent 自己决定记什么、调什么，无需自研检索逻辑。
- **原生 MCP、模型无关、开源可自部署**。

```

│                  游戏引擎 (UE5)                 │
└──────────────────────┬────────────────────────┘
                       │
┌──────────────────────┴────────────────────────┐
│              ① MOD 层（引擎侧插件）              │
│   感知采集 · 动作执行 · 能力暴露为 MCP Tool       │
│            【唯一引擎耦合层】                     │
└──────────────────────┬────────────────────────┘
                       │  MCP（Tool 调用 + 感知）
┌──────────────────────┴────────────────────────┐
│              ② MCP 层（无状态桥接）              │
│   聚合 Tool · 转发调用 · 转发感知                │
└──────────────────────┬────────────────────────┘
                       │
┌──────────────────────┴────────────────────────┐
│         ③ Agent 层 = Letta（每 NPC 一个有状态 Agent）│
│   · 内置分层记忆（core/archival/recall）         │
│   · 自主记忆管理 + 上下文管理                     │
│   · 通过 MCP 调用游戏 Tool                       │
│   · 持久化、跨重启记住                            │
└──────────────────────┬────────────────────────┘
                       │
┌──────────────────────┴────────────────────────┐
│              ④ Foundation 基础服务              │
│   Letta Server │ LLM(经网关) │ 存储(PG) │ 监控   │
└───────────────────────────────────────────────┘
```

> 相比激进版，**去掉了独立的 Social & World 层**，Agent 层由 Letta 承担并内置记忆。

### 1.1 各层职责

| 层 | 职责 | 说明 |
|----|------|------|
| ① MOD 层 | 感知采集、动作执行、能力→MCP Tool | 与激进版一致，唯一引擎耦合点 |
| ② MCP 层 | 无状态桥接、转发 | 与激进版一致 |
| ③ Agent 层（Letta） | 每个 NPC = 一个 Letta 有状态 Agent | **核心：记忆与决策全交给 Letta** |
| ④ Foundation | Letta Server + LLM 网关 + 存储 + 监控 | Letta 自带记忆存储 |

## 2. NPC = 一个 Letta Agent

### 2.1 映射关系
- **每个 NPC 对应一个持久的 Letta Agent 实例**。
- NPC 的人设 → Letta 的 **persona（核心记忆的一部分）**。
- NPC 的经历 → Letta 的**归档/召回记忆**，自动积累。
- NPC 的动作能力 → 挂载到 Letta 的 **MCP Tool**。

### 2.2 NPC 配置示例（映射到 Letta）
```yaml
npc_id: blacksmith_tom
letta_agent:
  persona: |
    我是汤姆，村里的铁匠，经营铁匠铺二十年。
    性格耿直、热心、话不多。我重视手艺和与村民的关系。
  human: |          # Letta 用于记录"对话对象"的记忆块
    （运行时动态填充当前交互对象信息）
  tools: [go_to, say, play_emote, interact]   # 经 MCP 挂载
  memory_blocks:
    core: 人设 + 当前目标
    archival: 长期经历（自动归档）
```

### 2.3 决策流程（依赖 Letta 内建循环）
```
① MOD 层感知 → MCP 层 → 注入 Letta Agent（作为 message/event）
② Letta 内部：检索相关记忆 → LLM 推理 → 决定动作
③ Letta 调用 MCP Tool → MCP 层 → MOD 层执行
④ Letta 自动将本次交互写入记忆（无需外部干预）
```
> 关键：**记忆的存、取、反思全部由 Letta 自动完成**，团队无需自研记忆流。

## 3. 社交机制：去中心化的 NPC 记忆

保守版**不建立全局社交网络图**，NPC 间的"社交感"完全依靠**每个 NPC 各自的主观记忆**来实现。这是一种去中心化、主观化的社交模型。

### 3.1 核心机制
- **主观关系认知**：每个 NPC 的 Letta Agent 在自己的记忆（`human` 记忆块 + 归档记忆）中记录对他人的认知，例如"安娜是我的朋友，她常来买面包，上次还帮我照看铺子"。
- **各记各的、无全局真相**：没有统一的关系权重表。汤姆眼中的安娜与安娜眼中的汤姆是**两条独立的主观记忆**，可能并不对称——这反而更接近真实社交。
- **对话即社交**：NPC 之间的交流通过 MOD 层"听到对方说话" → 作为感知事件注入各自的 Letta Agent → 触发回应，并由 Letta 自动沉淀为记忆。
- **关系自然演化**：随着交互增多，Letta 的记忆自动积累与更新，NPC 对他人的态度**自发地随经历改变**（无需显式的关系演化规则）。

### 3.2 优势
- **零额外开发**：完全复用 Letta 的记忆能力，不需要任何社交图/关系管理代码。
- **主观真实感**：每个 NPC 有自己的视角与偏见，社交更自然。

### 3.3 明确的局限（保守版主动放弃的）
- 没有全局社交网络视图（无法查询"整个社区的关系图谱"）。
- 没有统一的关系权重与演化规则（关系是模糊的自然语言记忆，非结构化数值）。
- 没有群体协作调度（NPC 不会主动分工协同完成共同目标）。
- 信息传播依赖直接对话，无系统性的"八卦扩散"机制。

> 这些局限是保守版换取"低风险快落地"的自觉取舍，也是与激进版拉开差异、供汇报对比的关键点。

## 4. 技术选型

| 层 / 模块 | 选型 | 理由 |
|-----------|------|------|
| MOD 层 | UE C++ 插件（MCP Tool） | 与激进版一致 |
| 通信 | MCP + 长连接 | 与激进版一致 |
| MCP 层 | MCP Server/Router（无状态） | 与激进版一致 |
| **Agent 层** | **Letta（自部署 Server）** | 有状态记忆开箱即用，省自研 |
| 记忆存储 | Letta 内置（PostgreSQL 后端） | 无需自建向量检索逻辑 |
| LLM | 经网关，模型可切换 | 保降本/迁移 |
| 部署 | Docker + K8s（Letta Server + 约 5 个 Agent） | 云端 |
| 可观测性 | Letta 自带 + Langfuse | 追踪记忆与决策 |

---

## 5. 迁移复用性

| 场景 | 改动范围 |
|------|---------|
| 换引擎 | 仅重写 MOD 层（Agent 层 Letta 不动） |
| 换游戏 | 改 NPC 配置（persona/tools），Letta 复用 |
| 换 Agent | ⚠️ 若换掉 Letta，记忆机制需重建（有状态耦合较深） |

> 注意：Letta 的**有状态记忆是深度耦合的**——记忆存在 Letta 内部。这带来复用便利，但也意味着**若未来想换掉 Letta，记忆迁移成本较高**（一个需权衡的取舍）。

---

## 6. 保守版优劣总结

**优势：**
- ✅ 开发成本低、落地快、风险小（核心能力用现成）。
- ✅ 单 NPC 记忆深度强，"记得住、会成长"是很好的汇报亮点。
- ✅ 记忆全自动，团队专注接入与配置。

**劣势 / 取舍：**
- ⚠️ 无全局社交网络与群体协作，"社区生机"弱于激进版（社交仅靠去中心化记忆近似）。
- ⚠️ 关系是模糊的自然语言记忆，非结构化数值，不便于系统性分析与调控。
- ⚠️ 记忆与 Letta 深度耦合，未来换框架成本高（已知取舍，MVP 阶段可接受）。

> 注：MVP 仅约 5 个 NPC，故有状态 Agent 的资源开销与规模化不构成顾虑，无需休眠等机制。

## 7. 落地路线（保守版）

| 阶段 | 目标 | 交付 |
|------|------|------|
| C0 | 打通 引擎↔MCP↔Letta | MOD 插件 + MCP 层 + 单个 Letta NPC 闭环 |
| C1 | 单 NPC 记忆与对话 | persona 配置 + 记忆验证 + MCP Tool 挂载 |
| C2 | 多 NPC 共存 | 约 5 个 Letta Agent + NPC 间对话（感知转发） |
| C3 | 打磨与产品化 | 配置工具 + 监控 + 汇报 Demo |

---

**结论**：本保守版以 **Letta** 承载 NPC 智能，用"**单 NPC 深度记忆**"作为核心卖点与"生机"来源，**社交仅靠去中心化的 NPC 记忆实现**，主动放弃全局社交网络与群体协作，换取**低风险、快落地**。MVP 阶段约 5 个 NPC，规模无忧。本版作为向管理层展示的**稳妥备选**，与激进版形成"快而稳" vs "强而进取"的清晰对比。
