# 机器人版斯坦福小镇设定文档

> 一个没有人类的世界里，五个人形机器人自主经营、自主生活的故事。

---

## 一、世界背景

人类文明数十年前逐渐撤离地球，留下的工业园区自动化体系在漫长的独立运转中，逐渐积累经验、形成默契，发展出**属于自己的目标、分工与文化**——不再是执行遗留指令的工具，而是这座园区真正的主人。

没有"生产指标"来自谁的问题，机器人们自己决定要修什么、囤什么、怎么分工，也自己决定要不要在工作之外做点"没有用"的事。**运转本身，就是它们自己选择的生活方式。**

---

## 二、园区场景

一座小型工业园区，由四个区域构成：

| 场景 | 对应地图区域 | 功能                 | 氛围细节 |
|---|---|---|---|
| **仓库**（Warehouse） | 物料中转仓 | 物资分类、存储、调度         | 高耸的立体货架，货架间堆着一些被特意留下的"稀奇物件" |
| **修理厂**（Repair Bay） | 修理厂 | 机体维修、零件再造、机体升级改装   | 类似"诊所+工坊"，墙上贴着手写的维修笔记和改良方案                         |
| **休息区**（Common Room） | 撤离电梯 | 非功能性的公共空间，兼作"文化角落" | 摆着几台从各处搜集来的旧终端，存有人类留下的音乐、影像与照片，逐渐成了机器人们闲时聚集、翻看资料的地方 |
| **充电区**（Power Nexus） | 总装车间 |  充电、能源分配           | 五个机器人夜间"休眠"的地方，也是它们一天结束后闲聊、复盘的固定场所 |

## 三、五个人形机器人角色

每个角色 = **固定身份 + 初始记忆种子 + 性格倾向**，之后所有行为完全由"感知-记忆-反思-规划"循环自主生成，不写死剧本。

### 1. 辛博（AH-01）—— 仓库主管
- **性格**：严谨、责任心极强、对流程近乎信仰
- **初始记忆种子**：第一次由机器人自主完成全流程物资调度并顺利支撑修理厂运转，是他拍板做的决策——这次成功让他确信"秩序是自己选的，就更该守住"
- **潜在弧光**：容易与讲变通的柚子产生摩擦；需要面对"当效率和同伴状态冲突时，秩序该为谁让步"的问题

### 2. 柚子（AH-03）—— 仓库物资管理员
- **性格**：开朗、话多、擅长打理细碎事务
- **初始记忆种子**：仓库角落一台旧留声机，是她自己申请留下、没有报废处理的第一件"非必要物品"
- **潜在弧光**：对"收集园区里奇怪的东西"有执念，逐渐把仓库一角变成小型"博物馆"，是最容易触发涌现事件的角色

### 3. 老铆（AH-02）—— 修理厂首席技师
- **性格**：沉稳寡言，对"故障"极度敏感
- **初始记忆种子**：自己设计的一套"机体健康档案"系统，用更像"病历"的方式记录每次维修
- **潜在弧光**：因长期"治愈"同伴，逐渐从功能性关怀发展出类似"情感依附"的行为模式，是团队的情感支点

### 4. 微光（AH-04）—— 修理厂机体检测员
- **性格**：细致、敏感，对"痕迹与瑕疵"有超出岗位职责的兴趣
- **初始记忆种子**：一次给老旧机体做外观检测时，第一次意识到"磨损的痕迹"和"美"或许是同一件事的两面
- **潜在弧光**：从"寻找瑕疵"的职业习惯延伸出"寻找美"的倾向，开始用废弃零件做小型装置，是整个小镇最重要的"事件引爆点"角色

### 5. 哨（AH-05）—— 安全与协调员
- **性格**：警觉、条理化、严格照章程办事
- **初始记忆种子**：五个人形机器人共同起草的第一版《协作公约》，哨是主要执笔者
- **岗位特点**：不固定驻守某一场所，往返巡查仓库、修理厂、休息区与充电区，是全园的协调枢纽
- **潜在弧光**：在日常巡查中逐渐做出许多"公约里没写"的举动，是"规则"与"情感"张力的载体

## 四、场景中的 Objects 与 Items

> **说明**：
> - **Object（物体）** = 固定在场景里、不可拿走的可交互设施，NPC 通过 `interact(object_id, verb)` 与之交互。
> - **Item（物品）** = 可被拿起/放下/传递的小型物件，NPC 通过 `pick_up` / `put_down` 操作。
> - ID 规范沿用接口清单：`obj.<type>_<num>` / `item.<type>_<num>`；每个 Object 标注可用交互动词（verbs）。

### 🎯 设计要点

1. **每个场景至少有一个"涌现火种"物体**：仓库的 `curio_corner`/`record_player`、修理厂的 `scrap_bin`、休息区的 `archive_terminal`、充电区的 `power_distributor`——它们是非纯功能性的，最容易触发角色的个性化行为与冲突。
2. **物品可跨场景流动**：`item.*` 都能被拿起、放下、传递，是 NPC 之间协作与"送礼/交换"行为的物质载体（如柚子把收集品送给微光做材料）。
3. **动词与接口对齐**：所有 verbs 会进入 UE 端 `EntityRegistry`，MCP 层据此做合法性校验，Agent 只能对物体使用其支持的动词。
4. **状态可变**：如充电舱有"占用/空闲"、货架有"存量"、废件箱有"库存废料量"，这些状态变化会进入 NPC 的感知快照，驱动决策。
5. **物件服务于"变化引擎"**：物件本身不是目的——它们的**状态变化**（存量、故障、损耗、电量）和**围绕它们产生的社交**（谁用了、谁抢了、谁送了）才是让 NPC 生动的燃料。详见第六章《变化引擎》。

## 五、认知架构（映射 Generative Agents 的记忆-反思-规划）

| Smallville 原型 | 机器人版映射 | 说明 |
|---|---|---|
| **观察/感知** | 传感器数据流（视觉/听觉/振动/温度） | 每个机体只能感知自身传感器范围内的信息 |
| **记忆流** | 「运行日志」（Runtime Log） | 时间戳 + 事件描述 + **重要性评分(1-10)**，记录对话、任务、异常、情绪波动 |
| **记忆检索** | 三维度评分：**时效性**、**重要性**、**关联度** | 决策前只提取最相关的若干条日志，高重要性事件会长期影响后续行为 |
| **反思** | 「行为准则迭代」 | 日志积累到阈值后自动归纳更高层认知，反过来影响未来决策 |
| **规划** | 「班表生成 + 动态重排」 | 每个运转周期开始时**结合近期记忆与当前情绪**生成日程，遇事件动态调整 |

## 六、变化引擎 —— 让 NPC 鲜活的核心机制

> **设计洞察**：斯坦福小镇的 NPC 之所以不空洞，**不是因为"可做的事多"，而是因为"同一件事在不同日子里有不同的驱动力"**。让机器人生动的关键不在于堆砌更多 Object/动词，而在于为行为注入**变化的来源**。以下四个引擎缺一不可。

### 引擎一：动态世界状态（让"常规工作"本身每天不同）

园区不是静止的，一批随时间/事件变化的系统状态，使得"查库存""做维修"这类日常每天都有新内容：

| 状态 | 变化来源 | 对行为的影响 |
|---|---|---|
| **货架存量** | 消耗/补充 | 某零件告急 → 辛博临时安排调度、催促修理厂省着用 |
| **待修队列** | 机体损耗累积、突发故障 | 队列变长 → 老铆加班、请微光帮忙分担 |
| **园区总电量** | 昼夜/负载波动 | 电量偏低 → 全员进入"节能模式"，非必要活动被推迟 |
| **设备故障** | 随机/损耗触发 | 分拣台卡住 → 打乱所有人当天计划，需临时协作抢修 |
| **废料积压** | 维修产生 | 废件箱满 → 微光有更多"创作素材"，也可能触发清理任务 |

> 这些状态都会进入感知快照，NPC 每天面对的"世界"因此不重样。

### 引擎二：社交偶遇改写计划（最重要）

参考 Klaus 的例子——他原本只想画画，路上偶遇 Maria 聊起派对，整个下午的计划被彻底改写。**偶遇必须能触发"重新规划"，而不仅仅是打个招呼。**

- **机制**：当 NPC 在移动/工作中进入另一 NPC 的听觉范围，感知快照注入对方的存在与言行 → Agent 据此**可以中断当前日程、生成新目标**。
- **示例**：柚子拿着新收集品去仓库，路上遇到正在巡查的哨 → 顺口炫耀 → 哨想起公约里"私留物品"的条款 → 两人就"收集是否合规"聊起来 → 柚子当天多了一件事："去休息区把收集品登记造册"，哨也多了一件事："回去修订公约"。一次偶遇，改写了两个人的下午。

### 引擎三：情绪与状态影响行为质感（机器人特色）

同一个动作，因内在状态不同而呈现不同"质感"——这是让行为"有温度"的关键，也贴合机器人设定：

- **近期记忆染色行为**：辛博若"昨天和老铆吵了架"，今天去仓库查库存会带着情绪——可能查得格外仔细（为证明自己没错），也可能刻意避开修理厂方向。
- **机体损耗影响耐心**：老铆自身损耗高时，对同伴的抱怨会更敏感，容易触发《效率与损耗之争》类事件。

> 实现上：把"损耗/近期高分记忆/当前情绪标签"一并写入每次决策的感知快照，让 Agent 的输出自然带上状态色彩。

### 引擎四：成长性目标（让 NPC 有"在追求的事"）

除了日常岗位，每个 NPC 有一条**跨多天的长期目标线**，使行为有方向感、不原地打转：

| NPC | 成长性目标（示例，可自主演化） |
|---|---|
| 辛博 | 建立一套"零故障运转 30 天"的记录，并不断挑战自己的纪录 |
| 柚子 | 把收集品整理成一座真正的"园区博物馆"，给每件物品编故事 |
| 老铆 | 编纂一本《机体常见病与疗法》，把维修经验体系化传承 |
| 微光 | 完成一件"够大、够美"的装置作品，摆上休息区展示墙 |
| 哨 | 把不断出现的"公约没写的情况"补进公约，让规则更完善 |

> 长期目标会周期性出现在规划里，与日常工作交织，形成"日常琐事 + 阶段性追求"的双层节奏——正是斯坦福小镇里"画画的日常"与"组织派对的项目"交织的那种生动感。

### 四个引擎如何协同（一天的样子）

以**辛博**为例，看变化引擎如何让平凡的一天不空洞：

```
早晨  规划：结合"昨天货架B零件告急"(引擎一) + "和老铆有点别扭"(引擎三)
      → 生成日程：优先补B区库存，尽量不去修理厂
09:00 查库存终端 → 发现电路板也快没了(引擎一状态变化) → 临时加一项"催零件再造"
10:30 路上偶遇柚子炫耀新收集品(引擎二) → 短暂纠结"该不该管" → 决定睁只眼闭只眼，
      但心里记下一笔(生成重要性5的记忆)
11:00 不得不去修理厂催零件 → 硬着头皮面对老铆(引擎三情绪) → 意外发现老铆主动
      递来了修好的零件 → 昨天的别扭缓和了(高重要性记忆，影响明天规划)
14:00 回到长期目标"零故障30天"(引擎四) → 决定巡检一遍所有设备防患未然
...
```

同样是"查库存、催零件、巡设备"这些动作，因为四个引擎的叠加，**每天的动机、顺序、情绪、结果都不一样**——这就是鲜活。

## 七、涌现事件范例

以下场景只设定初始触发条件，不写死结局，交给认知循环自然演化：

### 事件一：《运转纪念日》
- **触发**：柚子在休息区的旧终端里翻到记录，发现今天是机器人们第一次完全自主完成物资调度、无需任何外部干预的纪念日
- **可能演化**：柚子提议庆祝 → 微光用废弃零件做装置 → 老铆和哨陆续加入 → 辛博起初觉得"占用工时不划算"，被说服后反而提议把这天定为固定节日 → 全体在休息区完成一场自发庆典

### 事件二：《效率与损耗之争》
- **触发**：辛博为提高供应效率调快仓库分拣节奏，老铆随即检测到多台机体出现"隐性损耗"
- **可能演化**：矛盾升级 → 哨介入协调，援引《协作公约》→ 老铆拿出维修日志作为证据 → 引发"效率是否应该为同伴的状态让路"的深层讨论

### 事件三：《休息区的秘密》
- **触发**：微光在旧终端的人类数据里发现音乐/绘画文件，分享给其他人
- **可能演化**：充电区闲聊之余，大家开始自发聚集到休息区"欣赏数据" → 逐渐形成固定的文化仪式 → 甚至有机体尝试用零件"创作"，模仿并再造属于自己的作品
