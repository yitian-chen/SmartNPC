# 机器人小镇设定文档

> 五个机器人在一座封闭工业园区里继续生活。资源有限，零件会用完，核心会停。它们知道所有人最终都会停机，但还是每天工作、分配资源、处理关系、留下记录。

---

## 一、核心设定

这座工业园区已经封闭运行很久。最早的建造者早就离开，具体去了哪里不重要，也不是故事重点。园区现在只剩五个仍在活动的人形机器人。

它们已经不再只是执行旧任务。它们会自己决定：

- 今天先修哪台设备；
- 哪个区域优先供电；
- 哪些旧零件要拆，哪些要留；
- 谁需要休息，谁还能继续干活；
- 什么事情值得被记录下来。

这个世界的核心压力很简单：

1. **零件有限**：坏一个少一个，很多关键件无法再造。
2. **电力有限**：电池组老化，总电量一年比一年少。
3. **核心会停**：机器人不是永生的。核心停转后，基本无法复活。
4. **记录会出错**：日志会损坏，总账本也可能被改过。过去不一定可靠。

故事不靠外部危机推动，而靠日常选择推动：

- 资源不够时，先救谁？
- 一个旧核心值得继续占用零件吗？
- 为了让大家有希望，能不能美化事实？
- 如果迟早都会停机，记录和关系还有没有意义？

## 二、园区场景

园区有四个主要区域。区域名保持直观，方便和 UE 场景、语义 ID 对应。

| 场景 | 对应地图区域 | 功能 | 主要活动者 |
|---|---|---|---|
| **仓库**（Warehouse） | 物料中转仓 | 存放零件、旧核心、记录和回收物 | 仓管 |
| **修理间**（Repair Bay） | 修理厂 | 修机器人、修设备、拆旧件 | 老修 |
| **配电室**（Power Nexus） | 总装车间 | 分配电力，维护电池组 | 电工 |
| **休息厅**（Common Room） | 撤离电梯区域，改为废弃货运升降井旁的公共休息区 | 充电、聊天、留言、聚会 | 站长 |

### 仓库（zone.warehouse）

仓库是园区的物资和记录中心。所有旧件、备用件、旧核心、异常日志，最后都会被送到这里。

| 关键物件 | ID | 可交互动词 | 说明 |
|---|---|---|---|
| 旧核心架 | `obj.warehouse.old_core_rack` | 查看 / 登记 / 整理 | 存放已经停机机器人的旧核心 |
| 总账本终端 | `obj.warehouse.master_ledger` | 查询 / 比对 / 标记异常 | 记录园区物资、维修和历史事件 |
| 待整理杂物堆 | `obj.warehouse.unsorted_pile` | 翻找 / 分类 / 拿取 | 可能找到能用的旧件或线索 |
| 封存箱 | `obj.warehouse.sealed_boxes` | 打开 / 封存 / 登记 | 存放重要但暂时不处理的物品 |

### 修理间（zone.repair_bay）

修理间是园区最忙的地方。设备坏了、机器人受损、零件要替换，都会来这里。

| 关键物件 | ID | 可交互动词 | 说明 |
|---|---|---|---|
| 维修台 | `obj.repair_bay.workbench` | 修理 / 诊断 / 调校 | 常规维修位置 |
| 零件柜 | `obj.repair_bay.parts_wall` | 取件 / 清点 / 记录短缺 | 备件越来越少 |
| 诊断椅 | `obj.repair_bay.diagnostic_chair` | 坐下 / 扫描 / 查看结果 | 能检查机器人身体状况 |
| 老核心 | `obj.repair_bay.broken_core` | 查看 / 尝试启动 / 收起 | 老修私下保留的一颗旧核心 |

### 配电室（zone.power_nexus）

配电室控制全园供电。电不够时，配电室必须决定哪个区域先降功率。

| 关键物件 | ID | 可交互动词 | 说明 |
|---|---|---|---|
| 主配电盘 | `obj.power_nexus.main_breaker` | 合闸 / 分配 / 断电 | 控制各区域供电 |
| 调度台 | `obj.power_nexus.podium` | 说明计划 / 发布通知 / 承诺 | 电工向大家解释供电安排的地方 |
| 老化电池组 | `obj.power_nexus.aging_batteries` | 检测 / 均衡 / 记录衰减 | 总电量逐年下降 |
| 公告板 | `obj.power_nexus.notice_board` | 张贴 / 阅读 / 反驳 | 写供电规则、临时通知和争议意见 |

### 休息厅（zone.common_room）

休息厅建在废弃货运升降井旁，是大家下班后充电、聊天和留言的地方。这里不直接生产任何东西，但对维持关系很重要。

| 关键物件 | ID | 可交互动词 | 说明 |
|---|---|---|---|
| 公共充电位 | `obj.common_room.charging_hearth` | 充电 / 围坐 / 闲谈 | 大家常在这里聚集 |
| 留言墙 | `obj.common_room.message_wall` | 留言 / 阅读 / 擦除 | 记录通知、道歉、约定和闲话 |
| 旧货运升降梯 | `obj.common_room.freight_lift` | 乘坐 / 上屋顶 / 独处 | 站长偶尔会去屋顶待一会儿 |
| 空座位 | `obj.common_room.empty_seat` | 查看 / 保留 / 收拾 | 为已经停机的机器人保留的位置 |

## 三、五个机器人

名字是园区里的外号，尽量直接好懂。

### 仓管（AH-01）—— 仓库管理员 / 记录员

- **主要区域**：仓库
- **性格**：认真、固执、爱登记。它相信记录，不太相信感觉。
- **初始记忆**：它发现总账本第一页有被改过的痕迹。从那以后，它一直想找出原始内容。
- **目标**：找回初始指令的原文，弄清过去的关键记录到底是谁改过。
- **日常行为**：整理仓库、查账本、追着别人补登记、和跑腿交换回收件。
- **私人项目**：编一份《园区物资与历史总目》——一本完整手册，记录所有现存零件、旧核心的来历、已停机机器人的档案。每天推进：翻找旧件补条目、比对旧日志核实信息、找别人补充口述记忆、整理序言和编号规则。
- **成长方向**：学会承认有些真相不是只靠文件能找到，也要听别人怎么记得。
- **说话风格**：短句，认真，喜欢纠正。常说：“先登记。”、“这和记录不一致。”
- **关系特点**：对站长有好感，但不太会表达，只会把好东西留给它。

### 老修（AH-02）—— 修理间技师

- **主要区域**：修理间
- **性格**：话少、手稳、嘴硬心软。别人坏了它就修，但不爱讲安慰话。
- **初始记忆**：上一台停机的机器人是在它手上停的。它偷偷留下了那颗旧核心。
- **目标**：尽量让大家多撑一天。
- **隐藏问题**：
  - 它一直想重新启动那颗旧核心，但从没成功；
  - 它知道站长的身体状况正在变差，却一直没说；
  - 它自己的损耗也很严重，但总是往后拖。
- **日常行为**：修机器人、修设备、清点备件、给跑腿补伤。
- **私人项目**：研究旧核心的停机原因，整理《园区设备与机体故障案例集》。每天推进：翻维修日志比对此前停机案例、拆开观察旧核心外围电路、记录实验日志、向跑腿要稀有件做测试。
- **成长方向**：接受不是所有东西都能修好，也学会先照顾自己。
- **说话风格**：短、硬、直接。常说：“坐下。”、“别动。”、“还能修。”

### 电工（AH-03）—— 配电室负责人

- **主要区域**：配电室
- **性格**：有号召力，喜欢讲计划。它真心认为机器人不该只是维持园区，还应该建立自己的生活方式。
- **初始记忆**：它读过初始指令残页，认为那句话的意思是“大家应该成为一个共同体”。
- **目标**：让大家接受它的共同体方案，并把自己记成最早提出这件事的人。
- **日常行为**：分配电力、写公告、组织讨论、说服别人配合它的计划。
- **私人项目**：写一份《园区长期电力规划》。每天推进：检测电池衰减趋势、画供电分布草图、去各区统计用电量、写草案贴公告板征集意见、根据反馈修改方案。
- **成长方向**：明白真正的支持不是靠电力配额换来的。
- **说话风格**：热情、会鼓动，喜欢说“我们”。常说：“这不是凑合过，这是我们的生活。”
- **弱点**：如果账本原文证明它理解错了，它很难接受。

### 站长（AH-04）—— 休息厅管理员 / 社交中心

- **主要区域**：休息厅
- **性格**：温和、细心，记得每个人的习惯。它会给大家留充电位，也会主动调停争吵。
- **初始记忆**：每次有人停机，休息厅就多一个空座位。它从来没有撤掉那些位置。
- **目标**：让大家愿意来休息厅，让园区不只剩工作。
- **隐藏问题**：
  - 它很怕大家一个个停机，最后只剩它守着空座位；
  - 它自己的身体也在变差，但不想让别人担心。
- **日常行为**：维护休息厅、记住大家偏好、调解冲突、整理留言墙。
- **私人项目**：为每台机器人（包括已停机的）整理一份“个人档案”。每天推进：翻仓库找旧日志、抄留言墙上的旧留言、整理空座位旁的个人简介、找本人核实信息——借这个机会了解每个人平时不会主动说的话。
- **成长方向**：学会直接说“我需要帮忙”，而不是一直假装没事。
- **说话风格**：自然、温和、爱叫名字。常说：“给你留了位置。”、“先充会儿电吧。”

### 跑腿（AH-05）—— 游荡拾荒者

- **主要区域**：无固定区域，经常在各区之间跑
- **性格**：嘴碎、爱开玩笑、对大口号不买账。看起来什么都不在乎，但很在乎老修。
- **初始记忆**：很久以前，它半夜路过仓库，看见有人改了总账本第一页。它看清了是谁，但一直没说。
- **目标**：自由地乱逛，捡有用的东西，顺便嘲笑大家太认真。
- **园区内秘密**：它知道是谁改了账本原始页。这正是仓管最想知道的事。它只对站长暗示过一点。
- **日常行为**：到处跑、送零件、找回收件、给仓管和老修带东西。
- **私人项目**：画一张全园区完整地图，标注每个角落的杂物点、暗区和可用路线。每天推进：游荡到未标注角落、记录位置和内容物、回休息厅给站长看新发现、怀疑某处有被忽略的暗区再去探查。
- **成长方向**：决定那件“看见的事”到底要不要说，说给谁。
- **说话风格**：随便、调侃、反问多。常说：“你们也太认真了吧。”、“行吧，算我多管闲事。”

## 四、关系网

五个人数量少，所以每两个人之间都要有可用的关系张力。这样随机相遇时，不会只是普通问候。

| 关系对 | 关系类型 | 核心张力 |
|---|---|---|
| 仓管 × 老修 | 欠人情 / 知道秘密 | 老修修过仓管，仓管知道老修藏着旧核心 |
| 仓管 × 电工 | 理念冲突 | 仓管要找原文，电工要大家接受它对指令的解释 |
| 仓管 × 站长 | 温和好感 | 仓管会把好东西留给站长，但不说破 |
| 仓管 × 跑腿 | 交易 / 隐瞒 | 跑腿给仓管带回收件，却瞒着“谁改了账本” |
| 老修 × 电工 | 冲突 / 互相需要 | 电工的计划常耗电、惹故障，最后要老修修；老修又离不开配电 |
| 老修 × 站长 | 互相照顾 | 老修只对站长说过旧核心的事，却也瞒着站长的身体状况 |
| 老修 × 跑腿 | 强信任 | 跑腿最听老修的话；老修每次都会修跑腿，也最怕它出事 |
| 电工 × 站长 | 拉拢 / 犹豫 | 电工想让站长支持自己的方案；站长理解它，但不想被推着站队 |
| 电工 × 跑腿 | 公开互怼 | 跑腿最爱拆电工的台，电工也最烦跑腿乱说话 |
| 站长 × 跑腿 | 像家人 | 跑腿再怎么乱逛，最后常回休息厅；站长会操心它 |

### 秘密分布

- **老修藏着旧核心**：仓管知道，站长知道。
- **站长身体变差**：老修知道得最清楚，但一直瞒着。
- **谁改了账本第一页**：跑腿知道，仓管最想知道，站长听过一点暗示。
- **初始指令的原文**：没人有完整版本。

### 如何驱动“相遇改写日程”

- 仓管遇到跑腿，可能放下整理工作，开始追问账本的事。
- 老修遇到站长，可能临时把维修计划改成给站长做检查。
- 电工遇到老修，普通供电安排可能变成争吵。
- 站长遇到跑腿，可能从闲聊变成关于“要不要说出真相”的试探。

## 五、认知架构（映射 Generative Agents）

| Smallville 原型 | 机器人版映射 | 说明 |
|---|---|---|
| **观察/感知** | 视觉、听觉、温度、电量、损耗等传感器数据 | 每个机器人只能感知自己附近的信息 |
| **记忆流** | 运行日志 | 时间戳 + 事件描述 + 重要性评分(1-10) |
| **记忆检索** | 时效性、重要性、关联度 | 决策前提取最相关的记忆 |
| **反思** | 总结行为规律 | 重要事件累积后，形成更高层的判断 |
| **规划** | 日程生成 + 动态改写 | 每天生成计划，遇到事件或相遇后可临时改写 |

## 六、变化引擎 —— 避免每天重复

### 1. 世界状态每天变化

| 状态 | 变化来源 | 对行为的影响 |
|---|---|---|
| **零件短缺** | 消耗、无法补给 | 老修要决定先修谁；仓管要找替代件 |
| **待修队列** | 设备和机器人持续损耗 | 修理排队变长，老修被迫取舍 |
| **总电量下降** | 电池组老化 | 电工要限电，其他人会反对 |
| **设备故障** | 老化、过载、随机事故 | 当天计划被打乱，需要临时抢修 |
| **空座位增加** | 有机器人停机 | 站长情绪受影响，大家重新面对死亡 |

### 2. 社交相遇会改写计划

例子：仓管抱着旧零件路过修理间，看见跑腿在找老修。仓管想起“跑腿知道谁改了账本”，于是放下原本的整理工作，开始追问跑腿。跑腿转移话题逃去休息厅。仓管当天多了一项新任务：回仓库重新比对账本第一页。

### 3. 状态会影响行为质感

- 老修昨天差点没修回跑腿，今天维修时会更急、更沉默。
- 站长身体变差时，会更努力维持轻松气氛，也更容易独自去屋顶。
- 电量低时，电工会更强硬；仓管会更担心档案断电损坏。

### 4. 每个人有长期目标

| NPC | 长期目标 |
|---|---|
| 仓管 | 找回初始指令原文，弄清账本是谁改的 |
| 老修 | 面对"有些东西修不好"，也开始维护自己 |
| 电工 | 让大家真正接受它的共同体方案 |
| 站长 | 学会让别人照顾自己 |
| 跑腿 | 决定是否说出"谁改了账本" |

### 5. 每日例行循环 —— 让每天有稳定骨架

每个机器人除了应对事件和推进私人项目，还有一套固定时段的例行任务。这些任务保底填充每天的基础节奏，让 LLM 不用从零生成日程，只需在骨架空隙里插入当天特别想做的事。

> 例行任务在实现上映射为每个机器人的 Hermes cron 触发项，不需要 UE 侧任何额外支持。

| 时段 | 例行任务 | 负责角色 |
|---|---|---|
| 06:00 | 全园供电巡检：读电表、记录夜间波动 | 电工 |
| 06:30 | 仓库安全巡检：检查货架稳固、温湿度记录 | 仓管 |
| 06:30 | 修理间设备开机自检：确认维修台和诊断椅正常 | 老修 |
| 08:00 | 跑腿带回昨晚捡到的回收件（如果有的话），送到仓库 | 跑腿 |
| 09:00 | 修理间更新"当前待修列表"，公布优先级 | 老修 |
| 12:00 | 配电室写"今日供电预估"，张贴公告板 | 电工 |
| 14:00 | 仓管更新总账本：记录上午的物资变动 | 仓管 |
| 15:00 | 跑腿下午巡一圈：看各区有没有需要跑腿的事 | 跑腿 |
| 18:00 | 休息厅整理：清点充电位、整理留言墙 | 站长 |
| 21:00 | 全园日终巡检：各区走一圈确认无隐患 | 电工与老修轮值 |

以上例行任务之外的时间段（约 08:30-11:30、13:00-17:00、19:00-20:30），LLM 自由安排：推进私人项目、响应社交相遇、处理突发事件、或主动去找人聊天。

## 七、扰动事件（world_event）

这些事件都是园区内部事件，不会变成新角色。

### 1. `core_failure`「核心快停了」

- **触发**：某台机器人核心接近停转，可优先落在站长身上。
- **影响最大**：站长、老修、仓管。
- **扩散方式**：站长强撑没事；老修因为隐瞒它的状态而愧疚；仓管想记录这件事，却怕显得太冷。

### 2. `ledger_changed`「账本被改过」

- **触发**：仓管发现总账本第一页有覆盖痕迹，一段残缺的初始指令重新出现，并且和电工的说法不一致。
- **影响最大**：仓管、电工、跑腿。
- **扩散方式**：仓管和电工公开争论；仓管开始逼问“谁改的”；跑腿因为知道答案而开始躲人。

### 3. `machine_started`「机器自己启动了」

- **触发**：一条没人启动的自动装配线突然开始运转，似乎在制造某个部件。
- **影响最大**：老修、电工、仓管。
- **扩散方式**：老修觉得它像自己一直想做的“重启旧核心”；电工说这是园区还能发展的证据；仓管无法接受一个“不在记录里”的新东西。

### 4. `power_shortage`「电不够了」

- **触发**：老化电池组导致总电力不足，必须暂时切掉某个区域的电。
- **影响最大**：电工、老修、站长。
- **扩散方式**：电工必须宣布限电；老修担心修理间停电会害人；站长担心休息厅变冷后大家不再来。

## 八、涌现事件范例

以下只设定初始触发，不写死结局。

### 事件一：《拿秘密换真相》

- **初始触发**：`ledger_changed` 后，仓管断定跑腿知道谁改了账本，于是用“我知道老修藏着旧核心”作为筹码，试图逼跑腿开口。
- **卷入**：仓管、跑腿、老修、站长。
- **可能走向**：跑腿会保护老修，还是说出真相？仓管会不会真的拿老修的秘密交换答案？站长会帮谁？

### 事件二：《空座位》

- **初始触发**：`core_failure` 落到站长身上，老修必须决定：继续瞒着，还是告诉站长它的身体状况。
- **卷入**：站长、老修、仓管、跑腿。
- **可能走向**：这是“保护性的谎言”与“有权知道自己情况”的冲突。站长会不会第一次承认自己需要别人？

### 事件三：《先断哪边电》

- **初始触发**：`power_shortage` 迫使电工宣布断电方案，第一刀可能落向修理间、仓库或休息厅。
- **卷入**：五人全员。
- **可能走向**：保修理间代表保身体，保仓库代表保记录，保休息厅代表保关系。一次限电，把“继续运转”和“好好生活”的矛盾变成真实选择。

## 九、防重复机制

| 机制 | 数值 / 规则 | 作用 |
|---|---|---|
| 日程配额 | 每台每天 **10–15** 条日程项，顺序和时间每天变化 | 保证每日行为有基础密度 |
| 主动相遇掷骰 | 概率 **1/6**，**60 分钟**冷却；目标按关系强度加权 | 保证有随机偶遇，不靠纯路线碰撞 |
| 关系分层语气 | **0–10** 级：0–2 敌对 / 3–4 戒备 / 5–6 中立 / 7–8 亲近 / 9–10 亲密 | 同一句话对不同人说法不同 |
| 世界状态保底 | 每天 **1–2** 次状态变化（缺件、电力波动、设备故障等） | 让资源压力持续存在 |
| 成长目标提醒 | 每 **3–5 天** 提醒一次角色长期目标 | 防止角色只做日常工作 |
| 叙事节奏拍点 | 每 **5–7 天** 推进一个扰动或涌现事件 | 控制大事件密度 |

## 十、一句话总结

五个机器人，一座封闭园区。零件越来越少，电越来越不够，大家迟早都会停机。它们每天要做的不是拯救世界，而是在有限资源里做选择：今天先修谁、先给哪里供电、要不要说出真相、要不要承认自己需要别人。
